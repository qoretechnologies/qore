# Phase 4 — migrate `qorus` top-level launcher to AOT

## Goal

Eliminate the Phase 0 source-embed pattern from the top-level
`/usr/bin/qorus` launcher.  Today it's still a classic source-bytes
binary that decompresses zlib-embedded Qore text at startup and hands
it to `qpgm->parse()`.  Port to the same per-file AOT recipe we used
for qctl/qbugreport/qdsp/qwf/qsvc/qjob.

- Installs the `Qorus` namespace via `qorus_init_pgm(*QNS)` (binding

- Calls ~30 `qorus_X(bool debug_qorus_internals, QoreProgram*,

## The recipe (proven for qwf/qsvc/qjob/qctl/qbug)

**CMake side:**

1. Collect the list of `.qc` / `.ql` sources currently feeding the
   Phase 0 init funcs into a variable `QORUS_MAIN_QO_SRC`.
2. Define a new cmake invocation using `qorus_qore2qo_batch` that:
   - Parses each source via `qcc -c --context=<dir> --stub=<stubs>`
   - Produces per-file `.qo` in `build/qo/QORUS/<file>.qo`
   - Then `qorus_qore2qo_agg` emits `QORUS_QO_AGG.cpp` containing the
     `qore_X_script_register(...)` dispatch table
3. Replace `QORUS_SOURCES` entries:
   - Remove: nothing (qorus_main.cpp stays)
   - Add: `${CMAKE_BINARY_DIR}/QORUS_QO_AGG.cpp` + the per-file `.qo`
     objects linked in via the same pattern as `QORUS_CORE_SOURCES`
     already does for `_SRC_X.cpp`

4. Add the `exec/qorus-compile-stubs.qc` file — lists every symbol
   the qorus main parse needs to see pre-declared (classes + module
   APIs used by `QORUS_PARSE_OPTIONS`).  Pattern: copy
   `qwf-compile-stubs.qc` as a starting point and trim.

**C++ side (`qorus_main.cpp`):**

1. Wrap the init-func call block with
   `qore_aot_script_begin_batch(qpgm) … qore_aot_script_end_batch(qpgm)`.
2. Replace each `qorus_X(...)` call with `qore_qorus_<file>_script_register(qpgm)`
   (the per-file register wrapper the aggregator emits).
3. `parseCommit` stays; `runClass("QorusMaster")` stays.

**Old glue to remove:**

- `/build/x_<file>.qr.cpp` / `/build/x_<file>.qc.cpp` (per-file
  embedded-source generated files)
- `qorus_X(...)` init-func forward declarations in `qorus_main.cpp`
- `qore2c` cmake invocations for these specific sources (keep it for
  any sources still on Phase 0)

## Ordering + dependencies

`qorus_main` has a fairly deep inheritance chain — `QorusMaster` at
the bottom depends on `AbstractQorusClientProcess` → `AbstractQorusClient`
→ `AbstractQorusClusterApi` → etc.  The batch-register path already
handles this via `QoreAOTBinaryMultiDeserializer` phase-sync (see
sessions 2026-04-19 p4 memory), so blob order is not load-bearing as
long as every dependency is included in the batch.

Verify with a fresh build that the full set compiles + links + runs.
Expect to hit one or two new cases during scale-up — e.g. init-func
order sensitivity if any of these sources has a runtime-evaluated
constant that another source's class-inheritance depends on.  Pattern
match those against the fixes in the p4 session (cross-session
importInheritedMembers / rebuildBaseClassSml).

## Operational dependencies

- `qorus_init_pgm` (builtins/namespace setup) must still run
  *before* the batch — unchanged.
- `parseCommit` must still run after the batch, on the same `qpgm`.
- `runClass("QorusMaster")` runs as-is.  The class is findable post-
  commit via the normal namespace lookup.

## Test strategy

1. Build `qorus` with the new `.qo` pipeline.  Confirm link cleanliness
   (no unresolved Phase 0 symbols).
2. `/usr/bin/qorus --version` end-to-end — exits 0, same output as
   pre-migration.
3. `/usr/bin/qorus --help` same.
4. Actual cluster startup in a dev environment — `ostart` / `ostop` +
   process lifecycle.  This is the real test: `qorus` spawns qctl /
   qwf / qsvc / qjob / qdsp / qorus-core under its own management.
5. Regression: AOTSmoke (93) + JITSmoke (156) unchanged, qwf
   wall-clock parity preserved.

## Risk

Medium.  The recipe is proven for 5 other binaries; `qorus` is more
complex because:
- Larger source set (~30 init funcs vs 8-11 for qwf)
- Runs as the cluster launcher — regressions affect the whole stack
- Has `QORUS_PARSE_OPTIONS` baseline that differs from the worker
  binaries; some classes may need different stub declarations

Mitigation: incremental migration is possible — port sources in
chunks (e.g. the cpc_* APIs first as they're self-contained, then
the Abstract* classes by inheritance order).  Each chunk goes
through batch-register + parseCommit, verify build + --version, move
on.

## Effort

- 0.5 day: cmake wiring + stubs
- 0.5 day: qorus_main.cpp batch migration
- 0.5 day: scale-up debug (expect 1-2 unknown-unknowns surfaced by
  the new code path)
- 0.5 day: verify cluster startup end-to-end
- Total: ~2 engineer-days.

## Payoff

- `/usr/bin/qorus` startup measured: likely similar delta to qctl
  (AOT phase much smaller than non-AOT startup overhead, so wall-
  clock gains may be modest).  But crucially: **the Phase 0 source-
  embed pattern is eliminated from the last launcher binary**,
  completing the Phase 3/4 migration sweep.
- Removes ~30 `x_<file>.qX.cpp` files from the build — cleaner
  layout, faster full rebuilds (no more zlib-decompress-into-parse
  on every build that touches these sources).
- Brings the parse-options / class-surface for `qorus_main` under
  the AOT compile-time check umbrella — any parse error in the
  embedded sources surfaces at qcc time, not runtime.
