# API Metadata Generation for Qore Modules

## Overview

QoreApiMetadata provides rich API documentation for the Qore Language Server (QLS)
by merging three data sources:

1. **Tree-sitter CST** — parsed from Qore source (`.qm`/`.qc`) files via `astparser`;
   provides doc comments, parameter names, and source-level structure
2. **Reflection API** — runtime type information from loaded modules; provides
   accurate types, inheritance, and overloaded signatures
3. **qpp `.meta.json`** — generated by the `qpp` preprocessor from `.qpp` files;
   provides documentation for C++ classes exposed to Qore

The merge pipeline (in `SymbolMerger`) prioritizes: AST docs > qpp docs > reflection
structure. This gives QLS access to documentation and type information for all Qore APIs.

## Problem

Previously, only the core `qore` repo generated `.meta.json` files from its 132+ qpp
source files. No metadata was generated for:
- **29 external modules** with 113 `.qpp` files — already generate `.meta.json` during
  build but never collected/installed them
- **16 external modules** with 48 `.qm` files — Qore-language modules with no metadata
- **Core qore repo** with 147 `.qm` files in `qlib/` — no metadata extraction

## Architecture

### Directory Layout

All metadata files are installed under a single root directory with per-module
subdirectories to avoid filename collisions:

```
/usr/share/qore/metadata/
    core/                    # core libqore qpp metadata (132+ files)
        qc_option.meta.json
        ql_io.meta.json
        ...
    core-qlib/               # core qlib .qm/.qc metadata (auto-extracted)
        Util.qm.meta.json
        DataProvider.qm.meta.json
        ...
    xml/                     # module-xml qpp + qm metadata (same directory)
        qc_option.meta.json  # no collision with core/qc_option.meta.json
        WSDL.qm.meta.json
        SoapClient.qm.meta.json
        ...
    json/                    # module-json qpp + qm metadata
        QC_JsonRpcClient.meta.json
        JsonRpcConnection.qm.meta.json
        McpClient.qm.meta.json
        ...
```

The `QORE_METADATA_DIR` CMake variable points to this root directory and is exported
via `QoreConfig.cmake` so external modules can discover it.

### QPP Metadata Generation

The `qpp` preprocessor (C++ in `lib/qpp.cpp`) already generates `.meta.json` files
via the `--metadata` flag. The `qore_wrap_qpp_value()` CMake macro supports a
`METALIST` parameter that collects generated `.meta.json` file paths:

```cmake
qore_wrap_qpp_value(QPP_SOURCES METALIST QPP_META_SOURCES ${QPP_SRC})
```

The `qore_install_qpp_metadata()` macro installs these into the per-module
subdirectory:

```cmake
qore_install_qpp_metadata(${module_name} ${QPP_META_SOURCES})
```

### Automatic QM Metadata Extraction

Metadata extraction for Qore-language modules (`.qm`/`.qc` files) is **automatic**
— it is integrated directly into the existing module registration macros:

- **`QORE_EXTERNAL_USER_MODULE`** — automatically extracts metadata from each `.qm`
  and `.qc` file it processes, using `_external_module_name` as the subdirectory name
- **`QORE_USER_MODULE`** — automatically extracts metadata when
  `QORE_QM_METADATA_EXECUTABLE` and `QORE_QM_METADATA_SUBDIR` are defined

This means external modules get QM metadata automatically just by using the existing
`qore_external_user_module()` calls — no duplicate file lists needed.

The `qore-extract-qm-metadata` script (installed to `$PREFIX/bin/`) performs the
actual extraction using `QoreApiMetadata::fromSourceFile()`.

### QLS Discovery

`QppDocIndex::buildFromDirectory()` recursively scans the metadata directory and
all subdirectories for `.meta.json` files, building a qualified-name-keyed index.
QLS loads this index at startup and uses it to provide hover documentation,
completion details, and signature help for C++ and module APIs.

## CMake Integration Guide

### Adding QPP metadata to a binary module

Two changes to `CMakeLists.txt`:

1. Add `METALIST` to `qore_wrap_qpp_value()`:
   ```cmake
   qore_wrap_qpp_value(QPP_SOURCES METALIST QPP_META_SOURCES ${QPP_SRC})
   ```

2. Install metadata with backward compatibility:
   ```cmake
   if (COMMAND qore_install_qpp_metadata)
       qore_install_qpp_metadata(${module_name} ${QPP_META_SOURCES})
   else()
       install(FILES ${QPP_META_SOURCES}
               DESTINATION ${CMAKE_INSTALL_DATADIR}/qore/metadata)
   endif()
   ```

### QM metadata for external user modules (automatic)

No additional changes needed. The `qore_external_user_module()` macro automatically
extracts metadata from each `.qm` and `.qc` file when `QORE_QM_METADATA_EXECUTABLE`
is available (set by `QoreConfig.cmake` when Qore >= 2.3 is installed).

### QM metadata via standalone macro (optional)

For modules that don't use `qore_external_user_module()`, the standalone macro is
available:

```cmake
if (COMMAND qore_extract_qm_metadata)
    qore_extract_qm_metadata(${module_name}
        qlib/Module1.qm
        qlib/Module2.qm
    )
endif()
```

### Core repo QM metadata

The core repo sets build-tree variables before the `qore_user_module()` calls:

```cmake
set(QORE_QM_METADATA_EXECUTABLE ${CMAKE_SOURCE_DIR}/bin/qore-extract-qm-metadata)
set(QORE_QM_METADATA_SUBDIR core-qlib)
set(QORE_QM_METADATA_ENV
    "QORE_MODULE_DIR=${CMAKE_BINARY_DIR}/modules/astparser:..."
    "LD_LIBRARY_PATH=${CMAKE_BINARY_DIR}")
set(QORE_QM_METADATA_DEPENDS qore astparser)
```

## Variables

| Variable | Description |
|----------|-------------|
| `QORE_METADATA_DIR` | Root directory for metadata (exported by `QoreConfig.cmake`) |
| `QORE_METADATA_DIR_OVERRIDE` | Override the default metadata directory |
| `QORE_QM_METADATA_EXECUTABLE` | Path to `qore-extract-qm-metadata` script |
| `QORE_QM_METADATA_SUBDIR` | Subdirectory name for `QORE_USER_MODULE` extraction |
| `QORE_QM_METADATA_ENV` | Optional environment for build-tree extraction |
| `QORE_QM_METADATA_DEPENDS` | Optional build dependencies for metadata targets |

## Files

| File | Purpose |
|------|---------|
| `bin/qore-extract-qm-metadata` | Metadata extraction script |
| `cmake/QoreConfig.cmake.in` | Exports `QORE_METADATA_DIR`, `QORE_QM_METADATA_EXECUTABLE` |
| `cmake/QoreMacros.cmake` | `qore_install_qpp_metadata()`, `qore_extract_qm_metadata()`, auto-extraction in user module macros |
| `qlib/QoreApiMetadata/QppDocIndex.qc` | Recursive directory scanning for metadata files |
| `qlib/QoreApiMetadata/MetadataStore.qc` | `fromSourceFile()` used by extraction script |
