# AOT automatic function-body outlining

Status: in development (2026-07)

## Problem

LLVM backend cost (SelectionDAG, regalloc, O3 function passes) scales
super-linearly with function size. A single pathological Qore function —
the motivating case is `QorusSchema::checkUpgrade(string)` with ~1,994 IR
blocks / ~18,428 IR instructions — dominates AOT module compile time
(~3 minutes, >12 GiB peak RSS) even when `OptimizeNone` skips the
function-level optimization pipeline, because instruction selection and
register allocation still process one enormous function. A manual source
split of the same method into seven helpers compiles in ~20 s / ~3.3 GiB,
establishing function granularity as the important boundary.

The fix must be transparent: users must not have to refactor giant
functions (see also the large `Qonsole*.qc` static methods in Qorus).

## Approach

Automatically outline safe single-entry/single-exit regions of a
pathological function's **Qore IR** into compiler-private helper
functions immediately before LLVM lowering, in the AOT driver only.
This generalizes the existing Phase 1.5 init-expression outliner
(`outlineInitExpression`, `lib/QoreAOT.cpp`), reusing its
`CallAOTHelper` instruction and helper-emission flow.

### Why this is natural in Qore's AOT model

- The AOT ABI is `i64 (ptr ctx, ptr xsink)`. `self`, `argv`, params and
  all non-IR-only locals are **not** function arguments — they live on
  the Qore thread-local variable stack, reached via `ctx` slot tables
  (`qore_rt_load_local_aot(ctx, slot, xsink)` etc.). A helper invoked
  synchronously with the coordinator's `ctx`/`xsink` therefore sees the
  identical execution context with no live-in/live-out marshalling.
- `CallAOTHelper` lowering (`lib/QoreIRToLLVM.cpp`) already passes
  `(aot_ctx_arg, xsink_arg)` and emits `emitExceptionCheck` after the
  call, so a helper that raises an exception (sets `xsink` and returns)
  stops the coordinator exactly like any throwing call.
- Exception cleanup inside the helper is generated by the normal
  per-function lowering (check-based EH, explicit `UninstantiateLocal` /
  scope-cleanup IR), so unwind behavior matches the inline original.

## Design decisions

1. **AOT-only pass.** Runs in `compileNamespaceFunctions` for both the
   function-variant and method-variant paths, after `tryLowerFunction`
   produced the IR. JIT/interpreter/tiered execution never see outlined
   IR. Not run in `metadata_only` mode (helpers are internal to the
   object file; metadata declares only the coordinator).
2. **Slot map from the original.** `buildAOTSlotMap` runs on the
   *un-outlined* function before the transform. Outlining only moves
   instructions (never creates instructions that reference new slots),
   so the map covers coordinator + helpers, and metadata-only compiles
   (`qcc -m --from-objects`) assign identical slot ids without running
   the transform.
3. **Outline → lower → un-outline.** The transform destructively moves
   `unique_ptr` blocks into helper `QoreIRFunction`s and records exact
   undo information. After LLVM lowering of helpers + coordinator, the
   inverse transform restores the original object (same instruction
   pointers, same order). `cf.debug_ir`, `extractHandlerIRs`,
   `extractAOTSlotIdentities` and QORD serialization then see the
   original IR — the serialized debug IR stays interpretable (the IR
   interpreter rejects `CallAOTHelper` by design).
4. **Helper identity.** Named `<coordinator_llvm_symbol>_outline_<idx>`
   (deterministic; the coordinator symbol is already `_qaot_<mod>_`
   prefixed and unique). Emitted in the same LLVM module,
   `ExternalLinkage`, with `NoInline` so LLVM cannot re-inline them into
   the coordinator. Helpers are lowered before the coordinator so
   `getOrInsertFunction` resolves. Helpers return Nothing (v1 regions
   produce no value); no runtime descriptor is emitted (same as init
   helpers — the coordinator drives them via direct native calls).
5. **Region discovery: SESE interval sweep over the block layout.**
   First, a reversible *block-split pre-pass* breaks blocks at
   statement-end markers (`DiscardTemps`/`CheckException`/
   `UninstantiateLocal`/`ScopeExit` clusters, inserting an explicit
   fallthrough `Br`), because region boundaries can only sit on block
   boundaries and an `if`-merge block typically holds the merge point,
   the following statements, and the next branch in one block.  A phi
   naming a split head as incoming predecessor is repointed to the tail
   (the head's terminator moved there) and restored on unsplit.

   A candidate region is then a contiguous layout interval `[a..q]`
   (greedily grown to a target instruction count) such that:
   - no external edge lands on an interior block — any number of entry
     edges to `a` are fine (the transform retargets them all to the
     synthesized call block);
   - every edge leaving the interval targets exactly `F = q+1` — an
     `if` group's skip edge counts as a normal exit, which is what makes
     big guarded top-level statement groups (`if (version < X) {...}`)
     and fully-contained loops outlinable; back edges are allowed once
     their source joins the interval; a growth cap (4x the target size)
     abandons intervals that will not close before becoming one
     enormous helper (e.g. a whole giant loop swallowed from before its
     header) so later starts partition the construct's body instead;
   - no exception-kind edge (instruction `exception_target`) leaving
     the interval — even to `F` (rewriting it into a helper return
     would skip an in-function handler path);
   - neither the first block nor `F` contains phis or
     landingpad/catch-entry instructions;
   - no SSA value crosses the interval boundary in either direction
     (live-through coordinator values are fine);
   - paired temp marks and `ScopeEnter`/`ScopeExit` ids stay inside
     (the lowering pairs them through function-local state);
   - referenced locals classify cleanly (below); weak-assigned (`:=`)
     locals must not cross the boundary; a shared local's lifecycle op
     may sit inside the region only if the local has no references
     after it (the common `for`-init-in-previous-block shape);
   - the function entry block is never part of a region.

   Reference-promoted closure-use locals may cross the boundary when
   the function creates no closures: every access goes through the
   thread-global CVV stack, so the helper resolves the coordinator's
   CVV and stays coherent by construction (crossing locals are not
   helper body locals, so the helper never pushes its own CVV).  This
   does not apply to functions with exception paths when the crossing
   local is used through a parse reference (`\local`, including
   reference iteration): exception cleanup can unwind nested
   closure-use locals before the helper runs, leaving the helper unable
   to recover the coordinator-owned CVV.  Such regions are rejected,
   while regions without a crossing parse-reference local remain
   eligible.  When the function contains a `CreateClosure`, closure-use
   locals must not cross the boundary — real captures interact with the
   CVV stack (especially under recursion) in ways the helper boundary
   does not preserve.
6. **Trigger.** Internal default thresholds on IR size (instructions /
   blocks) chosen so ordinary functions are never touched; only
   pathological functions pay the (small) helper-call overhead.
   `QORE_AOT_OUTLINE_FN=0` disables the pass;
   `QORE_AOT_OUTLINE_FN_MIN_INSTS=<n>` lowers the trigger for tests.
   `QORE_AOT_DEBUG` prints region/helper diagnostics.
7. **Crossing locals demoted from IR-only.** A local referenced by more
   than one piece (coordinator or any helper) must not live in private
   LLVM allocas per piece. Such locals are removed from
   `ir_only_locals` (and the native int/float unboxed-alloca sets) for
   every piece, forcing TLS write-through + reload-after-call via the
   existing non-IR-only machinery. Locals confined to a single piece
   keep full alloca optimization within it. Helpers mark crossing
   locals pre-instantiated (the coordinator or the caller instantiated
   them).
8. **Self-recursive fast entry.** When the outliner fires, the
   Approach-B fast entry is skipped: fast-entry mode passes params as
   LLVM arguments (not TLS), which helpers cannot see, and a
   pathological function does not benefit from the fast entry anyway.
9. **In-region `return` token.** Giant loop bodies (the
   `driveDesignAgentLoop` shape) are full of early `return` statements;
   regions may contain them.  Each return moved into a helper is marked
   with a transient `outline_signal` flag: its lowering calls
   `qore_rt_outline_signal_return()` (a thread-local flag) immediately
   before the ret — nothing can run between the signal and the
   coordinator's consume, so the flag is nesting-safe.  The
   coordinator's `CallAOTHelper` carries a transient `return_target`
   pointing at a synthesized block that re-executes
   `Return <call result>` through the coordinator's own epilogue (the
   helper's return value is the in-region return's value; NOTHING for
   valueless returns).  The lowering consumes the flag with
   `qore_rt_outline_take_return()` after the call's exception check and
   branches accordingly.  Early-return cleanup clears
   (`uninstantiate.local`) of shared locals inside regions are safe:
   AOT lifecycle ops only clear the runtime value, and the
   coordinator's re-executed return skips pre-instantiated locals.
10. **Fused int-op coherence.** Fused local ops
   (`increment.local.int`, `add.assign.local.int`,
   `br.if.lt.local.int`) on shared locals stay coherent through the
   TLS stack: their loads run `ensureLocalCacheFresh()` and their
   stores write through for non-IR-only locals.  Coordinators of
   outlined functions create the local reload epoch **eagerly** in
   `lowerFunction()` — block layout order does not follow control flow,
   so a loop condition lowers before the helper-call block that bumps
   the epoch and its stale check would otherwise be silently skipped
   (this manifested as an infinite loop: the fused `while` condition
   never observed the helper's `++turn`).

## Correctness invariants

- Normal fallthrough through an outlined region is indistinguishable
  from inline execution: same TLS locals, same temp-mark discipline
  (balanced within the helper), same side-effect order.
- An exception inside the helper: helper-local cleanup runs in the
  helper (generated by its own lowering), the helper returns with
  `xsink` set, the coordinator's post-call exception check routes to its
  own unwind path — the same sequence a real nested call produces.
- Outlining disabled (`QORE_AOT_OUTLINE_FN=0`) must produce behavior
  byte-identical to the outlined build (test matrix requirement).

## Non-goals (v1)

- Regions with `break`/`continue` crossing the boundary — rejected by
  discovery (the exit-convergence rule); a control-token generalization
  of the return token could support them later.
- Giant single `switch` statements (every case is entered from the
  dispatch block — no single-entry interval exists).  These need either
  a two-level switch split or data-driven source (`sourceText`-style
  tables); the `OptimizeNone` big-function guard remains the fallback.
- Live SSA values across region boundaries (an explicit result/control
  token can be added later if profitable).
- Regions inside `try` blocks or scopes whose handler/cleanup edges
  leave the region (the exit-convergence rule rejects them; fully
  contained try/catch and scopes outline fine).
- Parallel per-helper backend compilation (separate work; helpers being
  whole functions makes them natural units for it).

## Measured result (2026-07-18, original unsplit QorusSchema.qm)

`checkUpgrade(string)` (2,422 IR blocks / 18,840 instructions; 2,850
blocks after splits) partitions into 10 helper regions (coordinator: 80
blocks).  Full module compile with `qcc -m -O3`, same machine and tree:

| metric    | outlining disabled | outlining enabled |
|-----------|--------------------|-------------------|
| wall time | 2:37.8             | **0:30.8** (5.1x) |
| peak RSS  | 9.60 GiB           | **1.85 GiB** (5.2x) |
| qmod size | 39.3 MB            | **13.0 MB** (3.0x) |

The manual seven-way source split of the same method (the performance
oracle) measured ~19.7 s / ~3.3 GiB / 12.6 MB.

### Giant-loop shape (return token; synthetic `driveDesignAgentLoop` analog)

A synthetic agent-loop function (one `while` over 700 guarded statement
groups with early returns and fused int counters; 11,206 IR blocks /
63,733 instructions — modeled on the Qorus
`QorusQonsoleCore::_static_driveDesignAgentLoop` build pathology):

| configuration                      | compile wall | peak RSS  |
|------------------------------------|--------------|-----------|
| no mitigation                      | > 10 min (killed) | —    |
| `QORE_AOT_BIG_FN_THRESHOLD=200` (OptimizeNone) | 7:14 | 7.2 GiB |
| outlining (41 regions, full -O3)   | **0:28**     | **0.35 GiB** |

Runtime output is identical to the interpreter in all configurations.
Note the OptimizeNone guard alone does NOT fix the pathology — LLVM
instruction selection and register allocation remain super-linear on
the one giant function regardless of the optimization level.

## Verification

- `examples/test/ir/AOTFunctionOutlining.qtest` — forces low thresholds
  via `QORE_AOT_OUTLINE_FN_*` and compares outlined compiled output with
  interpreted output for: sequential statement groups, exceptions +
  `rethrow` + `on_exit` inside regions, static + instance methods,
  reference args and container locals, object lifetime/destructor order,
  disabled-mode equivalence, no-safe-partition fallback (loop with
  embedded returns), and deterministic helper naming.
- The full `examples/test/ir/` suite passes both normally and with
  outlining forced onto nearly every function
  (`QORE_AOT_OUTLINE_FN_MIN_INSTS=60`).
- valgrind (Debug build): compile with forced outlining and execution of
  the outlined binary are error- and leak-clean.
- Remaining production validation (tracked separately): full Qorus AOT
  build including the large `Qonsole*.qc` static methods, Qorus
  regression tests against the outlined `QorusSchema.qmod`.
