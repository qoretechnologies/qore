## Test harness and fixes found during verification

`live_lifecycle.py` is opt-in and invokes `LiveAction.q` over private subprocess pipes. Successful
responses can contain SAS locations/copy authorization tokens, so raw bridge output must never be
logged. The parent logs only controlled outcomes, HTTP statuses and identifier-shaped error codes.
Synthetic PDFs are generated with the Python standard library and need no committed binary assets.

The runner uses unique names, checks destinations before creation and registers owned objects only
following accepted submissions or successful copy authorization. Azure authorization reserves a
model: GET then returns HTTP 400 with ModelNotReady, while DELETE supports cleanup. The runner
therefore does not mistake the reservation for a pre-existing customer model, and can delete its own
reservation even when copy submission fails. Authentication errors never qualify as successful
absence checks. Active training at a timeout is reported as incomplete cleanup, with its identifiers,
rather than claiming cleanup succeeded or deleting data still needed by the operation.

Initial test-harness errors were corrected: Blob upload needed PUT, fields.json needed an array of
fieldKey definitions, the receipt training class needed Layout OCR results, and a top-level Qore
failure must return its exit status directly. The first copy attempt stopped at an overly strict
second absence check after authorization; its reserved destination was subsequently deleted with
204/404 verification, and both copy lifecycles passed after correction. Failed attempts are not
counted as successful live tests. No provider implementation defect was exposed by these runs.

Microsoft's [classifier training guide](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/how-to-guides/build-a-custom-classifier?view=doc-intel-4.0.0)
requires matching Layout API results for each training document. The fixture generator now uploads
those API response envelopes alongside every training PDF.

## Reproduction

From the repository root, after `az login` into the intended subscription:

```sh
cmake --build build --target AzureDocumentIntelligenceDataProvider-qmod Mime-qmod -j6
QORE_MODULE_DIR=build/qlib-qmod:qlib LD_LIBRARY_PATH=build python3 -B examples/test/qlib/AzureDocumentIntelligenceDataProvider/live_lifecycle.py --account QorusTestFoundry --resource-group Qorus_Dev --provision-storage --temporary-role
python3 -B examples/test/qlib/AzureDocumentIntelligenceDataProvider/test_live_lifecycle.py
QORE_MODULE_DIR=build/qlib-qmod:qlib LD_LIBRARY_PATH=build build/qore -penable-debug examples/test/qlib/AzureDocumentIntelligenceDataProvider/WireContracts.qtest
QORE_MODULE_DIR=build/qlib-qmod:qlib LD_LIBRARY_PATH=build build/qore -penable-debug examples/test/qlib/Mime/mime.qtest
```

`--provision-storage` explicitly permits creation and cleanup of the temporary storage account;
`--temporary-role` permits adding/removing the narrowly scoped assignment if not already present.
Existing assignments are preserved. Use `--only entra`, `figure`, `storage`, or `training` to limit
a rerun; `training` includes model/classifier copy. The verified feature groups completed in focused
invocations while fixture problems were corrected, rather than one uninterrupted initial run.
