## CI findings and corrections

Pipeline 57163 exposed an empty-binary Base64 defect through RestSchemaResponseValues.qtest.
The value had logical length zero but its buffer was not NUL-terminated. JSON serialization
therefore read uninitialized capacity, producing allocator-dependent nonempty text. Both
QoreString binary constructors now initialize the empty buffer before Base64 concatenation.
The new core test checks JSON serialization as well as logical length, through the function
and binary pseudo-method with default and explicit line lengths. The existing nonempty Base64
and REST byte-serialization regressions remain intact.

The failure reproduced locally before the fix with `MALLOC_PERTURB_=85` in both the new core
test and the existing REST regression, while an ordinary allocation run passed. This explains
why the earlier successful local matrices did not catch it. After the fix, poisoned allocation
passes. A native C++ probe additionally checks getBuffer()[0] and strlen() for both constructors.

CI also exposed the credential-free AssemblyAI live suite calling QUnit main with no registered
cases. It now registers one explicit QUnit skip when neither an environment key nor a named
connection is provided. Configured live cases and assertions are unchanged. The guard tests
remove ASSEMBLYAI_APIKEY, ASSEMBLYAI_CONNECTION and ASSEMBLYAI_TEST_AUDIO from the environment.

One separate unchanged HTTP/2 external-service test received 502 from httpbin.org/status/500;
the same test passed on other platforms. Only that job was initially retried. After identifying
the two reproducible defects, the remaining pipeline jobs were canceled before pushing the fixes.
