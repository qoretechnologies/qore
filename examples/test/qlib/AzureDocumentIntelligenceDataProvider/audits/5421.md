## Connection, lifecycle, and shared repairs

Both connection constructors normalize/persist the Azure scheme and associate the app. They force a
GET resource-info ping and require integer model count/limit fields in a successful authenticated
response. Invalid keys, permission errors, 404s, malformed JSON and arbitrary HTTP-200 bodies fail.
The synchronous constructor now respects its connect argument. Key, explicit Entra token and legacy
authentication-header alternatives are mutually exclusive; unsupported inherited authentication modes
are rejected. Entra tokens are supplied and renewed by the caller; automatic refresh is not claimed.

Endpoints reject embedded credentials, fragments, query strings and unrelated paths. HTTPS is required
except for loopback HTTP fixtures. Polling and pagination links must retain the configured origin and
service path; unsafe schemes/hosts/ports, credentials, traversal and encoded path separators fail
before transport. Redirect following is disabled. Subscription headers are redacted in generic debug
echoes. Source URLs/bytes, storage SAS containers, classifier training sources and copy tokens are sensitive.

Each helper call owns its poller and closures; copied clients and concurrent jobs have independent
state. The deadline includes submission, fetches and sleeps, respects bounded Retry-After guidance,
and rejects a success arriving after the deadline. Failed, canceled, skipped and unknown states preserve
job/poll/last-status context without putting document bodies into diagnostic descriptions.

Wire fixtures identified shared defects, repaired at their owners:

- RestSchemaActions optionally returns typed status/header/body envelopes, preserving bodyless 202 jobs.
- RestSchemaDataProvider retains the original typed request before in-place validation, so byte fields
  are serialized exactly once; error logs retain the error class without sensitive response context.
- RestSchemaValidator preserves opaque `application/pdf` bytes, as it already does for image media.
- OpenApi3 creates independent response-direction type graphs accepting read-only fields and rejecting
  write-only fields through lists, maps, unions, derived types and repeated serialization. Cached request
  types remain unchanged. Copies share immutable schema ownership and memoize type nodes; they do not
  serialize an entire OpenAPI document per action. Direction-neutral documents retain their existing
  shared types: the repository-wide gate exposed excessive copying of Stripe's deeply interconnected
  types despite that document having no read-only/write-only properties. A property flag recorded
  during schema construction avoids that work. Per-traversal object-owned memoization avoids repeated
  filtering through nested typed hash references when a response copy is needed. A 25-level DAG fixture
  verifies that repeated descendants retain one copied identity.
- AsyncJobPoller validates positive limits, checks before/after fetches, caps sleep by remaining time,
  and retains structured timeout context without embedding private status content in descriptions.
