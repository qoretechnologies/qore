## Defect found by the live resource

The first nonempty resource response exposed a real defect absent from the earlier empty-list
checks: Google canonicalizes project IDs to project numbers in processor, version, and operation
names. A connection configured with `qorus-integration-engine` rejected the returned
`projects/444409446096/...` name as a different project. The initial read-only processor dropdown
failed; no documents had been submitted at that point.

The fix keeps request URLs scoped to the configured project. A numeric full name that differs from
that configured ID triggers a lazy authenticated `GET /v1/projects/<id>/locations/<region>`.
Only the returned location name can establish the canonical numeric alias. A supplied number alone
is insufficient. Location, collection, processor/schema parent, and final ID checks still apply.
Other named projects, unrelated numbers, other regions, and wrong parent paths remain rejected.

The verified alias cache belongs to the client and is keyed by project and location. Invalid results
are not cached. Same-origin copies establish their own cache. No cache mutex is held during network
I/O, so concurrent callers retain independent request deadlines; conflicting successful resolutions
are rejected. Static registration, schema materialization, and presentation never resolve projects.

Scoped native actions, processing, dependent references, and operation waiting consume this mechanism.
Waiting includes alias resolution in its overall deadline and retains the requested operation identity
when lookup or polling times out. Raw returned resource names remain intact for callers. Operation
responses must still contain a full resource name; a final review added a regression that rejects
a bare operation ID in a response, even though short IDs are valid request inputs.

The three-page live run and real deletion used the scope fix. A subsequent review tightened the cache
lock scope; that refinement was verified by a gated concurrent HTTP regression and a final real
read-only canonical lookup/ping/absence check. Paid OCR was not repeated solely for that internal
locking change or the subsequent malformed-operation-response check. Final read-only output:

```text
canonical_project=444409446096 ping=true owned_get_status=404 processors=0
```
