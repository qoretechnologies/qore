Scope and root cause
--------------------

The existing event-driven LlmCancellation implementation already closes in-flight
HTTP streams. Its cancellation checks were attached to transport reads, however,
so buffered structured output and callback fallback output could deliver a
completion after cancellation. Providers could also return success when the final
callback cancelled the token. The new regression cases reproduced these failures
before the implementation changed.

AbstractLlmProvider::deliverStreamEvent() checks cancellation before and after
each callback. OpenAI-compatible, Anthropic, Gemini/Vertex AI, Bedrock, and callback
providers use it for every event, including synthetic and terminal events. No
polling, new blocking operation, or transport workaround is introduced. Callback
exceptions retain the existing provider error handling. The original transport
cancel handlers and scope cleanup remain in place.

Changed files comprise six Qore module sources, three executable tests, global
release notes, and this audit. No C++, QPP, new module, or DataProvider action
registration changes are included.
