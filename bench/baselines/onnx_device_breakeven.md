# ONNX device-binding break-even

Generated by `bench/onnx_device_breakeven.qr` against `modules/ml/test/data/test_mlp.onnx`
(a compute-heavy MLP, `X(batch, 256) -> Gemm/Relu x3 -> Y(batch, 512)`; regenerate the
model with `modules/ml/test/data/gen_test_mlp.py`).

The sweep answers two questions:

1. **When does CUDA beat CPU?** (column *CUDA vs CPU*, CUDA device-retained vs CPU)
2. **When does keeping the output device-resident beat materializing it to host?**
   (column *retained vs materialized*) — this is the value of the device-binding feature.

## Result (RTX 3090 Ti / CUDA 12.4 / ONNX Runtime 1.24, 2026-05-30)

Median wall-clock over 12 iterations (3 warmup):

| batch | CPU ms | CUDA host-materialized ms | CUDA device-retained ms | CUDA vs CPU | retained vs materialized |
|------:|-------:|--------------------------:|------------------------:|------------:|-------------------------:|
|     1 |  0.116 |                     0.073 |                   0.062 |       1.87x |                    1.18x |
|     8 |  0.282 |                     0.099 |                   0.083 |       3.40x |                    1.19x |
|    32 |  0.951 |                     0.096 |                   0.074 |      12.85x |                    1.30x |
|   128 |  3.938 |                     0.160 |                   0.091 |      43.27x |                    1.76x |
|   512 | 15.506 |                     0.313 |                   0.147 |     105.48x |                    2.13x |

## Interpretation

- For a model with enough compute (this MLP does three 256–1024–1024–512 Gemms per row),
  **CUDA already wins at batch 1** (1.87×) and the advantage grows with batch size
  (≈105× at batch 512) as GPU throughput amortizes fixed launch/transfer overhead.
- **Device-retained output beats host-materialized output by 1.18× (batch 1) up to 2.13×
  (batch 512).** The gap widens with batch size because the device→host copy that
  materialization performs scales with the output size (512 floats/row → ~1 MB at batch
  512), while device-retained skips it entirely. This is the concrete payoff of keeping
  outputs device-resident for a downstream device-aware step.
- **Guidance:** enable device binding with `materialize_outputs: False` whenever a device
  output feeds another device-aware step; only materialize when host code must read the
  values. The crossover where retention matters most is larger batches and wider outputs.

## Caveats

- The shipped `test_linear.onnx` toy model is too small to show any of this — its compute
  and output (1 float/row) are dominated by fixed overhead, so CPU wins. Break-even
  numbers require a realistically-sized model like `test_mlp.onnx`.
- Absolute numbers are hardware-specific; the *ratios* and *crossover trends* are the
  portable takeaways.
